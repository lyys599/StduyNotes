# 机器学习建模总流程

## 1. 完整闭环

```mermaid
flowchart LR
    A["定义目标与指标"] --> B["划分数据"]
    B --> C["Pipeline预处理"]
    C --> D["简单基线"]
    D --> E["交叉验证与调参"]
    E --> F["封存测试评估"]
    F --> G["解释、误差与稳健性"]
```

## 2. 先定义任务

- $y$ 连续：回归。
- $y$ 为类别：分类。
- 没有 $y$：聚类、降维等无监督任务。
- 有时间先后：时间序列或带时间特征的监督学习，验证不可随机。

评价指标必须匹配代价：不平衡分类不要只看准确率，长尾回归不要只看 RMSE。

## 3. 基线先行

```python
from sklearn.dummy import DummyRegressor, DummyClassifier

reg_baseline = DummyRegressor(strategy="mean")
clf_baseline = DummyClassifier(strategy="most_frequent")
```

复杂模型若不能稳定优于基线，没有保留价值。

## 4. 通用交叉验证模板

```python
from sklearn.model_selection import cross_validate, KFold

cv = KFold(5, shuffle=True, random_state=42)
scores = cross_validate(
    pipeline,
    X,
    y,
    cv=cv,
    scoring=["r2", "neg_mean_absolute_error"],
    return_train_score=True,
    n_jobs=-1
)
```

训练分数远好于验证分数提示过拟合，但还应检查分布漂移和泄漏。

## 5. 模型比较应公平

- 使用相同数据划分；
- 使用相同评价指标；
- 所有预处理在各训练折内完成；
- 调参预算大致可比；
- 报告平均值与波动；
- 测试集只在最终方案确定后使用。

## 6. 输出不只是分数

至少包括：

- 基线对比；
- 交叉验证分布；
- 测试指标与区间；
- 混淆矩阵/残差；
- 典型错误样本；
- 特征重要性与稳定性；
- 运行时间；
- 局限和失效场景。

## 7. 论文表达

> 在相同分层五折交叉验证下比较 Logistic、随机森林和 XGBoost。全部预处理封装于 Pipeline。以 F1 为主指标、ROC-AUC 为辅助指标，并报告各折均值与标准差。最终模型确定后仅在封存测试集评估一次。

## 8. 易错点

- 只追求排行榜分数。
- 同一测试集反复调参。
- 不设简单基线。
- 忽略概率校准和阈值。
- 解释训练集的重要性，却不检验稳定性。
