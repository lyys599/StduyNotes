# 贪心算法

## 1. 核心思想

每一步选择当前看来最好的局部选项，并不回退。它速度快、易解释，适合作为优化基线；只有满足贪心选择性质和最优子结构时才保证全局最优。

## 2. 区间调度案例

选择最多个互不重叠活动。按结束时间从早到晚选择可证明最优：

```python
activities = [
    ("A", 1, 4),
    ("B", 3, 5),
    ("C", 0, 6),
    ("D", 5, 7),
    ("E", 8, 9),
    ("F", 5, 9)
]

activities = sorted(activities, key=lambda x: x[2])
chosen = []
last_end = float("-inf")

for name, start, end in activities:
    if start >= last_end:
        chosen.append((name, start, end))
        last_end = end

print(chosen)
```

## 3. 为什么有时失败

硬币系统 `{1, 3, 4}` 凑 6：

- 贪心先取 4，再取 1、1，共 3 枚；
- 最优为 3、3，共 2 枚。

所以“每次选最大”不是普遍最优。

## 4. 常见应用

- 区间调度；
- 最小生成树的 Kruskal/Prim；
- 非负边最短路径中的 Dijkstra；
- 部分背包按价值密度；
- 启发式初始解。

0-1 背包按价值密度贪心通常不保证最优。

## 5. 如何证明

常用交换论证：证明任意最优解都可把第一步替换为贪心选择而不变差，再递归处理剩余问题。

## 6. 竞赛用法

即使不能证明最优，贪心也可：

- 快速形成可行基线；
- 为 GA/SA 提供较好初始解；
- 评估复杂算法增益；
- 在时间紧张时提供可解释方案。

## 7. 论文表达

> 先构造按……排序的贪心基线，得到目标值……。由于问题不满足可证明的贪心选择性质，进一步采用整数规划/遗传算法，并将其相对基线的提升作为有效性证据。

## 8. 易错点

- 局部最优直接写成全局最优。
- 没有证明或反例检查。
- 排序准则无业务依据。
- 复杂算法没有与贪心基线比较。
