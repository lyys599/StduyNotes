# 多表合并与主键验证

## 1. 核心问题

表格合并不是“把两张表横着拼起来”，而是根据主键建立关系。合并前必须确认主键粒度：

- 一行代表一个人、一个城市，还是“城市 × 年份”？
- 主键在每张表中是否唯一？
- 重复键是错误，还是一对多关系？

## 2. 四种连接

| `how` | 保留范围 | 常见用途 |
|---|---|---|
| `inner` | 两表都出现的键 | 只分析匹配样本 |
| `left` | 左表全部 | 给主表补充字段 |
| `right` | 右表全部 | 较少使用 |
| `outer` | 两表所有键 | 查找未匹配记录 |

## 3. 最小可运行案例

```python
import pandas as pd

base = pd.DataFrame({
    "城市": ["A", "B", "C"],
    "年份": [2024, 2024, 2024],
    "GDP": [100, 130, 90]
})

pollution = pd.DataFrame({
    "城市": ["A", "B", "C"],
    "年份": [2024, 2024, 2024],
    "PM25": [35, 48, 40]
})

keys = ["城市", "年份"]

assert not base.duplicated(keys).any()
assert not pollution.duplicated(keys).any()

merged = base.merge(
    pollution,
    on=keys,
    how="left",
    validate="one_to_one",
    indicator=True
)

print(merged)
print(merged["_merge"].value_counts())
```

`validate="one_to_one"` 会在键不唯一时直接报错，防止无声地产生笛卡尔积。`indicator=True` 生成 `_merge`，显示每行来自哪一侧。

## 4. 合并前后的三项核验

```python
before_n = len(base)
after_n = len(merged)

print("行数变化:", before_n, "->", after_n)
print("未匹配数:", (merged["_merge"] == "left_only").sum())
print("新增列缺失率:", merged["PM25"].isna().mean())
```

若一对一左连接后行数增加，几乎可以确定右表键有重复。

## 5. 一对多和多对一

```python
orders = pd.DataFrame({
    "城市": ["A", "A", "B"],
    "订单额": [10, 20, 15]
})

city_info = pd.DataFrame({
    "城市": ["A", "B"],
    "地区": ["东部", "西部"]
})

result = orders.merge(
    city_info,
    on="城市",
    how="left",
    validate="many_to_one"
)
```

若两边键都重复，`many_to_many` 会产生组合扩张。除非业务明确需要，否则应先聚合或增加键。

## 6. 时间邻近匹配

两个表时间戳不完全相同，可使用 `merge_asof`，但必须先排序并设置容忍范围：

```python
left = left.sort_values("时间")
right = right.sort_values("时间")

out = pd.merge_asof(
    left,
    right,
    on="时间",
    direction="nearest",
    tolerance=pd.Timedelta("30min")
)
```

## 7. 论文表达

> 以“城市—年份”为联合主键连接经济与环境数据。合并前分别验证主键唯一性，合并时采用一对一左连接并记录匹配状态。合并后主表行数保持不变，未匹配率为……，因此未发生重复键导致的样本膨胀。

## 8. 易错点与练习

> [!warning]
> - 不要用行号作为跨表主键。
> - 合并键的数据类型和空格必须一致。
> - 主键重复时不要直接 `drop_duplicates()`，先查清重复的业务含义。
> - 合并后的缺失不一定是原始缺失，也可能是匹配失败。

练习：让右表的城市 A 出现两次，观察不使用 `validate` 时行数怎样变化，再用 `validate="one_to_one"` 捕获错误。
