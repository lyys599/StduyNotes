# VS Code断点调试与日志

> [!abstract] 学完本篇，你要能够
- 使用断点、单步执行和变量面板
- 区分日志与临时打印
- 为长流程保留可追踪记录

## 核心概念

- 断点暂停在指定行
- Step Over与Step Into用途不同
- `logging`支持级别和时间戳

## 手敲示例

先预测输出，再逐行输入；运行成功后至少修改三个值。

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s | %(levelname)s | %(message)s",
)
values = [2, 4, 8]
logging.info("开始处理，样本量=%d", len(values))
result = sum(values) / len(values)
logging.info("处理完成，均值=%.3f", result)
```

## 代码拆解

1. 日志模板把计算过程结构化。
2. 参数化日志避免手工拼接。
3. 在VS Code中给 `result`行设置断点并观察变量。

## 数学建模中的用途

比赛中一键运行可能持续数分钟，日志能说明程序卡在哪一步、使用了哪些参数。

## 常见报错与易错点

- 提交代码前到处残留无意义 `print`。
- 日志中不记录输入版本和随机种子。
- 只看最后一行报错，不看Traceback起点。
